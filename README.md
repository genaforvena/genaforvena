> I destroy the drawers of the brain, systematically discrediting everything.

Most of what is here is not a product. It is a **method run in public**: take a
machine — a language model, a mesh of phones, an ad exchange, a bass line — and
push it until it says something it was not built to say. Then keep the tape.

---

### The method

**Break it on purpose, then publish the break.**
A tool that has never been seen to fail is not a tool, it is a claim. The
interesting artifact is usually the failure, kept whole and dated, not the demo
that worked. `Finnegans-Fake` is a post-mortem on a replica that did not
happen — and it is the more honest half of the repo.

**An artifact, or it did not occur.**
Not "the camera works" — a non-zero JPEG. Not "the node is up" — a route the
kernel actually answers with. Every claim in these repos is supposed to have a
file behind it that you can open without me in the room. Where it does not, that
is a bug.

**Small, verifiable, portable beats large and plausible.**
Host shell rots per-platform and lies about it. Arithmetic does not.
Hence tiny ROMs that run byte-identically on x86 and a phone, instead of one
more clever script that only ever worked on the machine it was written on.

**Read the system from the side it does not expect.**
An ad exchange is loud about what it sells you and silent about what it says
about you — so read the bid request from the demand side. A hiring funnel is
opaque from the outside — so instrument it as correspondence, not as anecdote.
Point the instrument at the thing that assumed it was the observer.

**Constraint is the instrument.**
A deliberately incomplete writing system. A sampler with no notes, only grain.
A translation that must survive Masodov. A model asked to sing *Bobeobi*. The
limit is not an obstacle to the work; it is the entire mechanism of it.

### Bias, stated up front

I prefer the unfinished to the polished, the reproducible to the impressive, and
the negative result to the press release. Expect repos that stop mid-sentence
because the question ran out before the code did. That is not neglect — it is
where the interesting part was.

*If something here is wrong, it is wrong in public, with a timestamp.*
